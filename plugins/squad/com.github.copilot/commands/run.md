# Squad

Explore the repo with `git ls-files` and `rg`, never `find`.
Load the `squad` skill with the Skill tool by exact name `squad`; if that does not resolve, read `skills/squad/SKILL.md` relative to the squad plugin root (its `--plugin-dir`, as on the first line; a copy of this file in `.cursor/commands/` is not the root). The linters are at `../pack-check/skills/pack-check/scripts/` from that root. Never run `find` or any filesystem search for skills or linters. Never write `/squad` as prose
to load it. Then read `references/planning-contract.md` and `references/review-contract.md`. Read
the latest same-entrypoint `docs/retros/` file when present; carry its Lessons and Improvements as facts.
Resume: a resumed or stopped run that edits the plan (`## Status`) runs check-plan and does not continue until it exits 0. Retro catch-up first: if the newest plan in `docs/plans/` is still `Status: draft` and no `docs/retros/` file has its date-slug (with or without `-interrupted`), spawn `squad-retro` on that plan with reason `interrupted` before anything else; it writes `docs/retros/<yyyy-mm-dd>-<slug>-interrupted.md`. Then run check-retro on that file (not just `test -f`) and fix its findings before going on.

The main agent is the thin workflow controller. Specialists own their context.

Verify harness: when the change touches app behavior and `docs/verify.md` is missing, ask once `Make a runnable verify harness too? (yes/no)` as the skill says. Yes loads `verify-harness`; no carries on and writes no `docs/verify.md`.

1. Print the request, size route, every detected stack, the stacks applicable to this change, pack
   status, workspace, standards, repository conventions, and next action. Missing facts remain explicit.
2. For an obvious small change, write the tiny plan (goal, decision, verify command), then implement and verify directly: run the verify command, then the wider unit suite once. Do not call the planner, implementer, verifier, orchestrator, reviewers, or retro.
3. For a full loop, enforce language-pack readiness as described by the skill. Use `--no-pack` to continue a full loop after declining a missing language pack. After an approved installation, stop for a reload before creating `docs/plans/`. Small work may continue after reporting missing pack skills because its direct route does not depend on the plan-bound agents.
4. Invoke `squad-planner` in `next-round` mode with the request, evidence, `Facts to check`, decisions, user answers, and frontier. After round 1 writes the draft plan, run check-plan on it right away and fix its findings, then present exactly the returned numbered round to the user. Pass their answers and returned state into the next invocation. Repeat until the planner returns the shared-understanding confirmation. As soon as a round states the architect rule that fired (more than one layer, a new project or package, or a public API change), the main agent spawns `squad-architect` once with the draft plan path and passes its `## Design` and `## Map` into the next planner invocation, before `write-plan`. No rule fired: the plan says `Design: skipped (small)`. Planner returns `Design gap: <question>` → rerun `squad-architect` once with that question, then continue the planner; at most 1 rerun. Grill stays in these rounds; the main agent never grills itself; do not load a grilling catalog.
5. Before confirming, run check-plan on the draft and fix every error-level finding (em dash included; paraphrase quoted vendor text). After the user confirms, one Advisor-lite consult as defined by the skill, then invoke `squad-planner` in `write-plan` mode. The planner writes the draft plan .md from round 1, then finalizes it after confirmation. When stuck, one Advisor-lite consult; do not fan out.
6. If `## Slices` is missing or has one entry, invoke one fresh `squad-implementer` on the whole plan (spawn name: that slice or `whole-plan`; TDD, then stop; no full suite). Otherwise, for each `## Slices` entry in order, invoke a fresh `squad-implementer` for that slice only. Inside the loop, slice 1 included: write `## Status` (implementing slice i/N), run check-plan, wait for exit 0, then spawn the implementer. Every implementer spawn passes the slice name (or `whole-plan`) and the plan path; the slice's files come from its `## Slices` entry. An implementer returns `Plan gap: <question>` → run the planning contract's save command word for word, no substitutes, so `test -s "$p"` fails an empty patch and the run stops; it saves the partial diff (untracked included) to `$(git rev-parse --git-dir)/squad/<yyyy-mm-dd>-<slug>.gap-<n>.patch` (outside the worktree; never edit the product `.gitignore`), check it is non-empty and leave the tree as it is (saving fails → stop; use the contract's save command, which ends with `git reset -q`; no `reset --hard`, `clean`, `checkout`, or `restore`; planning-contract Gap markers), then run `git diff --stat`, then `squad-planner` in `next-round` mode on that gap only with that output and the patch path and present the question to the user; the answer goes to `## Grill log` and `## Decisions`; rerun `squad-architect` only for a design gap; then a fresh `squad-implementer` redoes that slice on the current tree with the updated plan path and the patch path to read. At most 1 Plan gap per slice; a second becomes `Replan:` for the whole plan and the retro records it. Then one `squad-verifier`, announcing the round number.
7. Resolve the product-diff pin (run files omitted). Empty or bad pin → stop before any reviewer spawn. Apply the review contract's Security gate: run `squad-security-reviewer` when the product diff touches auth, untrusted input, files, shell, crypto, dependencies, credentials, or exceptional conditions; otherwise skip. Record that reason. Do not launch a full-repo audit from this review. Directly launch `squad-reviewer`, `squad-simplifier`, and the conditional `squad-security-reviewer` in parallel against the product diff (run files omitted).
8. Give the completed reports, verifier evidence, round number, plan path, and security decision to
   `squad-orchestrator` for normalization, merge, and verdict only. If it returns an input error for a
   missing or malformed report, re-ask that producer **once** (hard cap: one re-ask per producer per review round), then merge again with the **same round number**. Never a second re-ask for the same producer in the same round.
   Never "keep fixing the report until it parses". Do not increment the round for parse repair. After a failed re-ask, or if the budget is spent,
   merge **once** with that axis marked `accepted, malformed after re-ask` **replacing** the bad payload (**non-blocking**), do not spawn that
   producer again. If input-error still returns after the marker was already supplied, stop and surface: no further merge. The orchestrator itself never retries or launches agents.
9. Every plan edit is a hard step: write, run check-plan, fix, and do not continue until it exits 0 (Status, fix list, hand-off notes, resumed or stopped runs too). Two plan edits in a row each get their own check-plan, or combine them into one write and lint that. Before any agent starts or the retro is written, the last plan edit must be followed by check-plan exit 0: before each implementer slice, before the fix-list implementer, before each reviewer round, and before `squad-retro` at hand-off. Linter path: the `pack-check` plugin folder, `skills/pack-check/scripts/check-plan.sh <plan>` (or `check-plan.ps1`); do not search the filesystem for it. No shell (calls rejected) at verify: stop and report `Environment block: no shell` before routing; spend no fix round on it. A rejected or failed linter call counts as not run, never as a manual pass. Route `fix`, `pass`, or `replan` as defined by the skill. A `fix` uses a fresh implementer
   invocation (spawn names `fix-list`); the author of the rejected code is not the fixer. Allow at most two fix rounds.
   After `pass`, or after two rounds with only residual `low`/`tiny` notes, at most one residual
   fixup may run as defined by the skill (never a third fan-out; failed spot-check → hand off).
10. Before handoff, one Advisor-lite consult as defined by the skill. Then hand off the plan path, files touched, criterion evidence, verdict, rounds, notes, pack status, workspace, and cleanup status. State that nothing was committed, merged, or pushed. Spawn `squad-retro` once with the plan or review path, last SHA, and interruptions; it writes `docs/retros/<yyyy-mm-dd>-<slug>.md` and nothing else. After `squad-retro` writes, run the `pack-check` skill's `scripts/check-retro.sh <retro>` (or `check-retro.ps1` without `sh`) and fix every finding in the retro before reporting Done; no linter or shell installed: skip and say so. A full run that stops or fails at any step also ends with this `squad-retro` spawn, passing the interruptions. A small change gets no retro. If this run evidenced a pack/skill/agent/command/contract change, append one suggestions entry. Do not apply it.
