Decision rules applied (PO + Sven, 2026-11-01):

- pstack: use upstream skills unchanged as pinned dependencies. Vendor (with source and licence) only if install as a dependency is impossible. Never rewrite. Result: every pstack row is installable per skill, so nothing is vendored.
- Matt: depend pinned, weave into our skill or playbook, or rewrite as our skill. All allowed under MIT with the copyright line in `NOTICE`. Matt's `pr` Summary text is Apache-2.0 derived (show-me), so weave only Evidence and Merge Danger, or carry an Apache-2.0 attribution.
- Every Matt skill ships `agents/openai.yaml` (Codex display metadata). Harmless if pinned; drop when woven.

Install legend for the table:

- **I-E**: per-skill pin in our `plugins/<plugin>/external-skills.json` (40-hex `commit`, `path` to the skill dir, `license`). Mechanism already exists on main (caveman). Publication materializes the dir unchanged onto `marketplace-beta`, and `ExternalSourceMaterializer.HideFromUserInvocation` adds `user-invocable: false` to the generated copy only. From there it ships to Claude, Copilot, Cursor/Grok and Codex as part of our plugin, and to gh-aw through `skills:` in the MAIN workflow at a 40-hex generated SHA or `aw.yml includes skills/<s>`.
- **I-P**: upstream whole-plugin install of pstack only. Cursor marketplace entry `pstack` in cursor/plugins `.cursor-plugin/marketplace.json`; Claude marketplace entry `pstack` -> `harness/pstack/claude-code` (generated tree, 58 skills). No upstream Copilot or Codex manifest found. Bundle, not per skill, not pinned by our tooling.
- **I-M**: upstream whole-plugin install of Matt: Claude plugin `mattpocock-skills` v1.3.2 (`.claude-plugin/plugin.json` lists 27 skills). Bundle only. chief-of-staff is not in that list.

## 3. Weave model (use upstream without forking)

How squad calls upstream skills:

- Registered skills (every pinned pstack skill and leaf): load with the Skill tool by exact name, as squad already does for `caveman`. Example line in a squad playbook: "Seed hypotheses with the **how** skill, then the **why** skill."
- Files that are not skills (poteto-mode `playbooks/*.md`, `architect/references/design-red-flags.md`): reference by path from the pinned sibling dir, `../poteto-mode/playbooks/bug-fix.md`, and pass the absolute path in every agent prompt (poteto line, section 4a).
- Squad keeps its own thin playbooks that point at upstream ones and add only squad gates (plan file, review contract, retro). Example: squad `playbooks/bug-fix.md` = "Run `../poteto-mode/playbooks/bug-fix.md`. Squad adds: failing repro in the plan, Matt diagnosing-bugs phase 1 loop, verifier evidence." No upstream text is copied.

## 4. Structure facts and caveats

### 4a. poteto-mode structure (exact)

- H1 `# Poteto mode`, then H2s in this order: `## Non-negotiables`, `## Principles`, `## Autonomy`, `## Subagents`, `## Writing the reply`, `## Comments`, `## Playbooks`. Non-negotiables comes before Principles.
- Bundled-skills line, verbatim (line 11, under the H1): "Bundled skills live at `../<name>/SKILL.md` from this file, so put this file's absolute path in every `poteto-agent` prompt."
- Principles opens with: "Read the leaf skill in full for any principle you apply. Each entry names when it applies. Each leaf is the **principle-<title>** skill, with the title in kebab case, hyphens kept and other punctuation dropped, unless the entry gives its name." Groups: Core (10), Architecture (6), Verification (5), Delegation (2), Meta (1). Each entry is one `**Title.** when-to-apply` bullet. Only Sequence Work into Verifiable Units spells its leaf name.
- Non-negotiables: cite only principles whose leaf SKILL.md was read this session.
- Playbooks: open a todolist whose first items are the matched playbook's steps copied verbatim; a skipped step keeps `skip: <reason>`. File = kebab title unless the entry names one. figure-it-out is the fallback; Orchestrate for standing programs. Playbook files start at H3 (`### Bug fix`).
- Playbooks reference principles three ways: `**principle-model-the-domain**`, "the **sequence-verifiable-units** principle skill", and bare `(principle-build-the-lever)`. Other playbooks by path (`playbooks/shipping.md`) or bold title (`**Opening a PR**`). Skills by bold name plus "skill" or by slash (`/deslop`).
- All pstack skills except setup-pstack and typescript-best-practices set `disable-model-invocation: true`. typescript-best-practices uses `paths: ["**/*.ts", "**/*.tsx"]`.

### 4b. gh-aw and provider caveats (from `ghaw-import-map.md`) for a principles index + leaf layout

- `skills:` in a shared fragment is silently dropped (P9, P10). Leafs ship only through main-workflow `skills:` at a 40-hex SHA (P11) or `aw.yml` + `gh aw add` (P19).
- `imports:` of a SKILL.md compiles but warns on `license`, `disable-model-invocation`, `user-invocable`, and `references/` do not come along (P3). Leafs must be installed as skills, not imported as prompt bodies.
- `#Section` import injects the whole file (P15). Separate leaf files are the right shape.
- Runtime frontmatter is kept only under `agents/` and `skills/` paths (P20).
- Agent files: max 1 per workflow, only from `.github/agents/`, not validated, so `model: standard` passes to Copilot verbatim (P4). Claude and Codex get the body as prompt.
- `../<name>/SKILL.md` (inferred, not run): works where sibling skill dirs are installed together. gh-aw installs to `.github/skills/`, `.claude/skills/` or `.codex/skills/` per engine, so a missing leaf fails silently at runtime.
- Remote `@main` fails offline (P14) and only warns in `skills:` (P12).

### 4c. Validator facts on main that decide "0 warnings"

- `ExternalSourceMaterializer`: imported skill without `user-invocable: false` is a `CompanyPolicy` diagnostic, which counts as an error (`Diagnostic.IsError` is true for everything except `Warning`). The materializer injects the flag on install, so pinned upstream skills pass unchanged.
- `SkillReferenceValidator`: every backticked `/name` must resolve to a skill or command in the same plugin or a catalogued external source. Needed: pin the whole closure, plus an allowlist for client built-ins (`/loop`).
- Not checked today (needed for the index + leaf layout): `../<name>/SKILL.md` path refs, bold principle names in an index, playbook file pointers.
- pack-author `make.md` bars: description starts `When ` and ends `.`, about 120 chars, router about 40 lines; past that review warns. A poteto-style squad hub is longer than 40 lines, so that bar needs a hub exception or it warns forever.
- Name rule (`make.md`): skill name differs from the command name. Main breaks it twice: skill `squad` vs command `squad`, skill `pack-check` vs command `pack-check`. The other pairs use the `-md` suffix (`scenarios-md`, `security-audit-md`, `pack-author-md`).

### 5b. write-skill.md (steps)

4. Write the Principles index: one line per principle with when it applies; link the leaf by name, never restate it.

6. List skill deps; add an `external-skills.json` record for each upstream one (closure).

### 5c. write-subagent.md (steps)

1. One role, one job; name = filename, `squad-*` or `<plugin>-*`.

4. Name the skills and principle leafs it loads by exact name, and the absolute path of the parent SKILL.md it receives.
5. State what it returns to the main agent (required fields), and that the main agent owns and re-reads its output.
6. `validate`, then check-subagent.
